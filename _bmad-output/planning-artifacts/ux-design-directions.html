UX Design Directions

DMCF Ticketing Stack Mapper

Four layout directions for the organisation list view. Each applies the agreed visual foundation (slate palette, blue-600 accent, Lucide icons, Tailwind tokens) with a different structural approach.

When evaluating each direction, consider:

✦ Filter controls — discoverable? ✦ Active filter state — always visible? ✦ Table density — right for the data? ✦ Compare affordance — unmissable? ✦ Capability states — scannable? ✦ Overall register — admin tool feel?

Direction 1 notes: Horizontal filter bar keeps the full table width available. Active filter chips provide persistent visibility of applied filters. Compare bar appears at the bottom when rows are selected — sticky and impossible to miss. Colour-coded provider badges (blue for Tessitura, violet for Spektrix, rose for Ticketmaster) create fast visual scanning. Capability icons (✓ / ✕ / –) are distinct at a glance. This is the recommended direction.

Direction 2 notes: The sidebar layout is familiar from enterprise tools. Filters are always visible and individually accessible. Trade-off: the sidebar consumes ~224px of horizontal space, which squeezes the table on narrower desktop widths. The "Apply filters" button introduces an extra step vs. reactive filtering in Direction 1. Good fit if Sam frequently adjusts multiple filters before applying, less so for quick single-filter queries.

Direction 3 notes: More rows visible without scrolling — 6 fit in the viewport here vs. 4 in Direction 1. All three capability columns (Mbr / Don / Seats) are visible simultaneously. Best suited if the catalogue grows large and scanning speed is paramount.

Direction 4 notes: The most generous spacing — rounded corners on the table container, larger row padding, bigger provider badges. Feels approachable and comfortable for less frequent users or longer reading sessions. Trade-off: fewer rows visible at once (4 vs. 6 in Direction 3), and the table container styling adds visual chrome that slightly reduces the "pure data tool" feel. City context is fully readable in the sub-row. Closest to a SaaS product register; furthest from GOV.UK admin.

Choosing a direction

You can pick one direction as-is, choose a base direction and modify specific elements, or combine aspects across directions. The design tokens (slate palette, blue-600 accent, capability icons, table header style) remain consistent across all four — only the structural and spacing choices differ.

Direction 1 ★
Best balance of filter visibility, table width, and reactive UX. Recommended for this tool.
Direction 2
Good if simultaneous multi-filter editing is the primary pattern. Narrower table.
Direction 3
Best for large catalogues where scan speed beats comfort. Consider for a second iteration.
Direction 4
Most approachable for infrequent users. Fewer rows visible; slightly more visual chrome.
