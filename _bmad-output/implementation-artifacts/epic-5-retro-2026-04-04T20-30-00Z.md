## Part 1 — What we shipped (from story records)

### Story 5.1 — Sample organisation seed data

- **17** curated organisations in `sample-organisations-seed-data.js` with **fixed UUID upserts** (ADR-014): four organisation types, multiple countries, Tessitura + United Kingdom row for the filter demo path, capability triplets spanning YES / NO / UNKNOWN, varied `created_at` and `last_updated`.
- Post-seed invariant ensures UK + Tessitura remains present; seed summary logging without noisy per-row output in CI.
- **Jest:** `sample-organisations-seed-data.test.js` — count, countries, types, capability variety, distinct timestamps, UK+Tessitura presence (review added explicit `created_at` variety per AC2).
- **Ops note in dev record:** Docker image rebuild sometimes needed so containers pick up seed changes; verified via `docker compose run --rm backend npx prisma db seed` and API curl.

### Story 5.2 — README completion and demo smoke test

- README: **Database seed and reset** for Docker (`exec` / `run --rm`) and local `backend/` workflow; distinction between Compose startup (`migrate deploy` + `db seed`) and manual re-run; ADR-014 semantics (`migrate reset` vs `db seed` vs user-created orgs); non-interactive **`migrate reset --force`** examples aligned with seed section.
- **Single ordered smoke checklist:** health, meta, shell, list, UK+Tessitura filter URL, compare (two selected + optional fixed-UUID deep link from 5.1), create → detail.
- **Known limitations:** no auth, desktop-first MVP, no CSV export, no external APIs — cross-referenced to threat model.
- **docs/decisions.md:** index extended for audit findability (through ADR-014); ADR-013 in compliance table; footer updated; README roadmap note removed.
- **Regression:** backend tests and frontend lint reported green in story record.

## Deep story analysis — patterns

### Common themes

- **Path drift (again):** Architecture / older prose sometimes says `backend/prisma/`; repo truth is `backend/src/prisma/`. Stories explicitly say *trust the repo* — still a recurring agent confusion surface.
- **Determinism vs demo richness:** Fixed UUID upserts (ADR-014) made idempotency testable; data module extraction supported Jest without spinning a full DB.

### Recurring review themes

- **Edge cases for operators:** When no backend container is running, use `docker compose run --rm` for `migrate reset` as well as `db seed`; document `--force` for scripts and non-TTY.
- **Wording precision:** API envelope described as top-level keys, not JSON-looking placeholders; module headers point to concrete ADR numbers (**ADR-014**).

### Breakthroughs

- **ADR-014** packages seed strategy so README, smoke steps, and implementers share one contract.
- **Story 5.1 → 5.2 pipeline:** Compare example IDs documented in 5.1 dev record flow straight into optional README deep-link smoke — reduces ambiguity without duplicating seed logic in prose.

### Technical debt / deferred

| Area | Item | Severity |
|------|------|----------|
| Seed | Sample upserts not in a single `prisma.$transaction` — partial state possible if seed aborts mid-loop | Low — acceptable for local/demo; revisit if CI depends on atomicity |
| Docs | ADR-011 rationale tone tightening (audit language) | Low — deferred in 5.2 review |
| README | Smoke checklist tied to exact seed IDs and filter URL — refresh when seed or routes change | Low — explicitly deferred |
| Tests | No scripted E2E runner for full smoke path | Medium — Epic 4 retro optional item still open |
| Planning | **SelectionContext** vs **SelectionProvider** naming in older epic prose | Low — Epic 4 action E4-1 still valuable |
