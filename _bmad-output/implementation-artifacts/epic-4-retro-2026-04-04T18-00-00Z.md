## Deep story analysis — patterns

### Common themes

- **Docs vs code names:** Epics still say `SelectionContext` in places; implementation uses `SelectionProvider`, `selection-context.js`, `useSelection.js` — story files explicitly warned against a second store; no production confusion, but **glossary alignment** remains useful for future agents.
- **Two sources of truth, on purpose:** Selection context for list checkboxes; **URL** for compare columns — enables shareable `/compare?ids=…` without session state.

### Recurring review themes

- **Accessibility:** `aria-disabled` vs native `disabled` for tooltips and keyboard — resolved toward native `disabled` where appropriate when over limit.
- **Robustness:** Non-object API success payloads must not collapse the UI (OrganisationCard).

### Breakthroughs

- **ADR-013** turned a spec/architecture tension into an explicit, traceable decision instead of silent drift.
- **`useQueries`** pattern for variable ID counts avoids rules-of-hooks violations and shares cache with detail views.

### Technical debt / deferred

| Area | Item | Severity |
|------|------|----------|
| API | No batch compare endpoint — intentional; N parallel GETs | Acceptable for MVP scale |
| Tests | Compare flows rely on manual QA + build in stories; no dedicated E2E in story scope | Medium — consider with Epic 5 smoke test |
| Docs | Radix import standardisation (carried from Epic 3 E3-1 / Epic 2 B2) | Low until next shadcn primitive |
| Backend | List validation test envelope hardening (Epic 3 E3-3) | Low — not blocking compare |
