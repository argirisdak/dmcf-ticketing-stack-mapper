## Part 1 — What we shipped (from story records)

**Story 2.1 — Organisation list**

- `GET /api/organisations` with pagination validation, `{ data, error, meta }`, list DTO for camelCase + ISO timestamps.
- Frontend: `useOrganisations`, table with skeletons (`isLoading` only), `Badge` + compact `CapabilityBadge`, empty state, row navigation, pagination UX.
- New ADRs in story trail: **ADR-009** (list DTO boundary), **ADR-010** (out-of-range `page` behaviour).
- Friction noted: Prisma generate in sandbox; tests mock Prisma/service layers; post-review hardening (query coalescing, response guards, tolerant `CapabilityBadge`).

**Story 2.2 — Create**

- `POST /api/organisations`, manual controller validation, FK checks, shared write validation path seeds for 2.4.
- **`COUNTRIES` moved to `backend/src/lib/countries.js`** — seed re-exports; aligns with Epic 1 retro intent (single canonical module vs only `seed.js`).
- GOV.UK-style error summary + inline errors, meta hooks, create flow + detail success banner.
- Tests expanded (e.g. 39 passing at story close per record).

**Story 2.3 — Detail**

- `GET /api/organisations/:id`, UUID vs missing row 404 parity, `toOrganisationDto`, labelled `CapabilityBadge` variant.
- **ADR-012** for 404 semantics; code review fixes: `location.state` preservation for banners, safe date serialization in DTO.

**Story 2.4 — Edit**

- `PUT /api/organisations/:id`, shared `parseOrganisationWritePayload`, strip client keys, shared FK validation with create.
- Shared form body, hydrate via `startTransition` (React 19), invalidation for list + detail keys.
- Review: client `capacity` max aligned with server; test for snake_case strip on PUT; deferred note on refetch vs concurrent edit (acceptable MVP risk).

**Story 2.5 — Delete**

- `DELETE /api/organisations/:id`, Radix/shadcn-style **Dialog** via **`@radix-ui/react-dialog`** (direct dep), mutation + list banner with `replace` state merge.
- Review: `console.error` parity on 500 tests; optional service-layer unit tests deferred.
