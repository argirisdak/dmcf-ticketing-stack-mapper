## 2. Story-Level Synthesis

### 2.1 What Went Well

- **Intentional regression strategy (8.2):** Story 8.2 explicitly documented that `OrganisationDetailPage` and `OrganisationFormPage` would render undefined fields after the API reshape, and accepted that as a known state to be resolved in Stories 8.4 and 8.5. This kept stories tightly bounded and allowed 100% completion.
- **`mergeParams: true` insight (8.1):** The Express sub-router gotcha — `req.params.id` returning `undefined` from the parent organisations router without `mergeParams: true` — was caught, documented in dev notes, and prevented future debugging.
- **`SystemCombobox` durability (8.3 → 8.4 → 8.5):** Built once with full accessibility (keyboard nav, ARIA, debounce, click-outside, URL pre-population), reused in 8.4 and 8.5 without modification. The `inputId`/`onSelect` API was stable from day one.
- **Same-day code review batch patching:** 10 review findings across 6 stories, 9 patched same day. Reviews were substantive — null safety, snapshot timing, form validation edge cases — not rubber stamps.
- **Backend pattern consistency:** The three-layer controller→service→DTO architecture from Epics 1–7 scaled cleanly to the junction endpoint. `toLinkDto` defined once in Story 8.1, imported (not re-defined) in Story 8.2 as explicitly planned.

### 2.2 Challenges

- **Null safety on nested relations (8.4 + 8.6):** `link.system` unguarded access appeared in code review findings for *both* 8.4 and 8.6. The DTO explicitly models `system: null` as a defensive case; the frontend assumed the field was always present. Same oversight, two stories in a row. Resolved via `linkedSystemPresentation()` helper in 8.6 and optional-chaining in 8.4.
- **Two-phase async submit deviates from mutation pattern (8.5):** `OrganisationFormPage.jsx` uses direct API calls instead of `useMutation` hooks for the link write orchestration. The reason is sound — `Promise.allSettled` must be awaited before navigation to determine which banner to show — but the pattern looks inconsistent to future readers without a comment explaining why.
- **`_rowKey` module-level counter bug (8.5):** Initial implementation used a module-level counter for stable React keys on link rows instead of `crypto.randomUUID()`. Caught in review and fixed. Minor but reveals that the "stable key" requirement wasn't fully thought through on first pass.

### 2.3 Recurring Review Themes

- Snapshot-at-click-time vs live-state for dialogs (8.4 remove dialog) — good catch, prevents stale copy bugs
- ARIA / label association for form controls in components (8.3, 8.4)

## 8. Team Agreements (Forward)

1. **Null-safety first pass:** Any component consuming a DTO field that can return `null` (especially nested relations like `link.system`) guards on the first write — not on review discovery.
2. **Deferred items with two strikes get promoted:** If a deferred item survives two epics, it becomes a required pre-condition for the next story that touches that area — not a backlog item.
3. **Async orchestration deviations are documented inline:** When the project's standard hook pattern must be bypassed (e.g. for `Promise.allSettled`), a comment in the file explains *why* — not just *what* — so future developers don't "normalise" it as the default approach.

---

## 9. Key Takeaways

1. **Intentional regression as a delivery strategy works** — Bounded stories with documented known regressions outperforms unbounded stories that try to fix everything in one pass.
2. **Null safety on nested relations is a recurring first-pass miss** — Two stories, same oversight. Build the habit; don't rely on code review to catch it.
3. **Deferred items need expiry dates** — A3 survived two epics. Anything deferred twice gets promoted to a ready-for-dev requirement on the next story that touches that surface.
4. **`SystemCombobox` is a durable investment** — Built once in 8.3, reused unchanged in 8.4 and 8.5. That return on quality validates the time spent building it right.
