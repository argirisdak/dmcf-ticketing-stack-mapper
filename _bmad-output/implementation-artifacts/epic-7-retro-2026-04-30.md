## 2. Story-level synthesis (implementation artifacts)

### 2.1 What went well (evidence from Dev Agent Records)

- **Backend parity with Organisation patterns:** New system stack (`system-list-dto.js`, `system-service.js`, `system-controller.js`, routes) mirrors proven list/detail/envelope behaviour; `buildSystemListWhere` extracted as a pure, testable function (`7-1`).
- **Hardening after code review:** `7-1` batch added safe pagination, `q` length guard, `console.error` on 500 paths, orphan junction handling in DTO, and `system-http-stack.test.js` so controller→service→DTO behaviour is exercised against real stack expectations.
- **Writes and conflicts:** `7-2` documented careful semantics (no-op PUT, capability `null` → `UNKNOWN`, DELETE sequence for restrict FK with surfaced org count for UX-DR42).
- **Frontend architecture:** `7-3` context split with **hook passed as prop** on `CompareSelectionBar` avoids Rules-of-Hooks violations; context split across `.js` / `.jsx` to satisfy `react-refresh/only-export-components`.
- **List UX:** `7-4` introduced `system-list-filter-params.js` with multi-value `category` + sorted query keys; skeleton only on `isLoading` (not `isFetching`), aligned with org list behaviour.
- **Detail UX:** `7-5` mirrors org detail patterns (`useSystem`, `useDeleteSystem`, 409 handling with `linkedOrganisationCount`, adoption grouping from pre-sorted API data).
- **Forms and tooling:** `7-6` shipped create/edit with field-level errors; Vitest isolated via `vitest.config.js`; Rolldown binding decision documented in root `CLAUDE.md` after review.

### 2.2 Recurring themes across reviews

- **Defer vs fix:** Several items explicitly **deferred** with rationale: nav/compare automated tests (`7-3`); URL `limit` for systems (`7-4`); `res.json()` on non-JSON errors (`7-4`); search input ↔ URL `q` sync (`7-4`); Vitest 409 duplicate-name + `fields` (`7-6`). Pattern: team chose shipping with documented follow-ups rather than expanding scope in-story.
- **AC alignment via review:** `7-5` reviews drove header badge placement, button order, skeleton completeness, `meta === null` parity on `fetchSystem`, and stricter URL checks for links.
