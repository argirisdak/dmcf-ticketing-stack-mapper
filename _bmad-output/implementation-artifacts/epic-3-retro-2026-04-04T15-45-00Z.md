## Part 1 — What we shipped (from story records)

### Story 3.1 — Text search

- Server `q` with debounced client (~300ms); `GET /api/organisations` extended; Prisma `OR` across name, **city**, notes, ticketing provider name; GIN trigram indexes for city, notes, provider name (name index pre-existing).
- **Schema / ADR alignment:** nullable `organisation.city` added; **ADR-002** updated in `docs/decisions.md` — resolves Epic 2 retro warning that epics text and ADR had diverged on `city`.
- Frontend: `useDebouncedValue`, query key `['organisations', { page, limit, q }]`, search slot above table, search-specific empty copy + clear search, page reset when debounced `q` changes (keyed `OrganisationListResults` pattern).
- Reviews: harden non-finite debounce delay; defer DTO `lastUpdated` vs `updatedAt`; defer keyed-remount a11y; defer `CONCURRENTLY` indexes for large DB ops; defer controller split.

### Story 3.2 — Filter bar and active filter chips

- Seven native `<select>`s in fixed order; URL via `useSearchParams`; values aligned with architecture (country labels, meta `name` strings, capability `YES|NO|UNKNOWN`).
- `ActiveFilterChips` + `organisation-list-filter-params.js` foundations; “Clear all” removes **only** the seven filter keys — forward-compatible with 3.3 (`q` / `page` preserved).
- Explicit non-goal: **no** filter args to `useOrganisations` until 3.3 — reduced risk by staging URL UI before API wiring.
- Reviews: shared `normaliseCapabilityParam` for chip/dropdown consistency; orphan country option for stale URLs; `meta.js` safe JSON parse on errors; `role="alert"` when meta queries fail.

### Story 3.3 — Multi-filter API + URL state

- Backend: list parses/validates country + capabilities; composite Prisma `where` — `q` OR-block **AND** exact filters on country, relations, capabilities; same `where` on `findMany` / `count`.
- Frontend: URL single source of truth for `page`, `limit`, `q`, and all seven filters; TanStack key  
  `['organisations', { page, limit, q, country, provider, type, crm, membership, donation, seating }]`.  
  Filter/search changes set `page=1`; pagination updates `page` only. Back from detail restores query string.
- Distinct empty states: search-only (3.1 copy) vs filter-active (“No organisations match these filters…” + clear filters without wiping `q` unless product says otherwise).
- Reviews: whitespace-only capability params treated as absent; clear search resets `page`; trim filter strings for UI/API alignment; JSDoc on filter section updated. Deferred: full AC7 error envelope assertions for some list validation tests; lowercase capability normalisation test; Prisma middleware removal follow-up; non-list files in large diff not re-audited in 3.3 review pass.

## Deep story analysis — patterns

### Common struggles (none catastrophic; mostly integration edge cases)

- **URL vs local state:** Evolution from React-only `q` (3.1) → split URL filters / local search (3.2) → full URL (3.3) required careful refactors (e.g. remove remount hacks where URL + query key suffice; search input remount on `location.key` for Back behaviour).
- **Consistency across UI and API:** Hand-edited query strings, whitespace, and invalid capability values forced extra normalisation and guards in chips, selects, and controller.

### Recurring review themes

- **Boundary validation:** List GET behaviour must match “omit empty” semantics across `q`, country, capabilities.
- **Accessibility:** Chips, `role="status"`, dismiss labels, meta load failures surfaced to users.
- **Documentation drift:** Stale comments and epic text vs implementation — caught and partially fixed during 3.1 (ADR) and 3.3 (JSDoc).

### Breakthroughs

- **`LIST_FILTER_PARAM_KEYS` + shared helpers:** “Clear all filters” semantics stayed consistent from 3.2 into 3.3.
- **Staged epic:** URL-first UI (3.2) before server AND-filters (3.3) made each PR easier to reason about than a single “big bang” change.

### Technical debt / deferred (tracked in stories)

| Area | Item | Severity |
|------|------|----------|
| API | Consolidate list DTO `lastUpdated` / `updatedAt` | Low — versioning story |
| DB | Trigram indexes without `CONCURRENTLY` | Ops — before large prod cutover |
| Backend | Split oversized organisation list controller | When next touching controller |
| Backend | Align some list validation tests to full AC7 error envelope | Test hardening |
| Frontend | Keyed list subtree remount — a11y follow-up if users report focus loss | Low |
| Repo | Prisma middleware removal — confirm no hidden reliance | Follow-up spike |
