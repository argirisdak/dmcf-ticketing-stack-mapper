## 2. Story-Level Synthesis

### 2.1 What Went Well

- **Sequencing matched dependencies:** Migration (`11-1`) → API (`11-2`) → read-only UI (`11-3`) → write UI (`11-4`) → seed (`11-5`) avoided blocked work and kept each slice testable.
- **Additive migration discipline:** `11-1` explicitly trimmed Prisma noise (`DROP INDEX` drift) — captured as **ADR-030**; same “SQL must match AC” muscle as earlier epics.
- **Contract clarity:** Allow-lists, `http(s)://` validation, empty-object clear semantics, and list responses including `fieldSources` are well specified and backed by Jest (`11-2`).
- **UX consistency:** One icon pattern, one form wrapper pattern, explicit **no row-level `sourceReference` fallback** for per-field icons — reduces ambiguous provenance.
- **Seed quality:** System and organisation coverage **exceeded** planning thresholds (`11-5`); strict “omit key if not defensible” policy resisted marketing-root padding.
- **Review culture:** Concrete patches (validation messages, `sourceErrors` merge, `normaliseFieldSourcesFromDto` type safety, `SystemCard` compare-only gating).

### 2.2 Challenges & Patterns (systems, not blame)

- **Prisma `--create-only` vs unmodelled indexes:** Recurring need to hand-edit migration SQL when the ORM emits drift — process cost is predictable; ADR documents the narrow exception.
- **Dual maintenance:** `field-source-keys` mirrored frontend/backend (ADR-016 / ADR-025 pattern) — correct for this stack; **any new surfaced field must touch both** or icons/forms silently miss keys.
- **Combined change-sets:** Several reviews note `sprint-status.yaml`, `package-lock.json`, and large planning-doc diffs bundled with feature work — improves local velocity, **raises review isolation and bisection cost** (same theme as Epic 10).
- **Story artifact vs code drift:** `11-2` “technical requirements” still described DTO-only / separate test files in places; implementation correctly wired services — **story templates should follow the code** to avoid reviewer confusion.
- **Forward dependency:** `11-3` deferred “extended capability rows on detail” until Epic 12 — acceptable, but **ordering Epic 11 before 12** meant UI completeness for those keys landed in the next epic (expected).

### 2.3 Recurring Review Themes

- **Validation parity:** Non-string `fieldSources` values, organisation POST coverage aligned with system.
- **State hygiene:** Replacing (not merging) server-mapped `sourceErrors` after narrowed 400 responses.
- **Compare vs list:** Icons only where product expects (e.g. `SystemCard` gated to compare grid).
